# Compliance Evidence Structure

Related issue: #17  
Source: HEDS-020 Compliance and Audit Manual

## Evidence categories

| Category | Evidence examples |
| --- | --- |
| Access control | Role definitions, permission checks, access review notes. |
| Audit | Sensitive action logs, admin changes, support access records. |
| Data quality | Data quality checklist, forecast traceability, validation failures. |
| Operations | Incident records, alert history, CI/deployment evidence. |
| Security | Secret handling, auth boundary, tenant isolation notes. |
| Legal/privacy | Privacy assumptions, terms/SLA dependencies, retention notes. |

## Evidence rules

- Evidence should be linked from relevant GitHub Issues or release notes.
- Sensitive evidence should not expose secrets or personal data unnecessarily.
- Acceptance decisions should cite evidence sources.
